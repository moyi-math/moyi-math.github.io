PostGIS 精度归约避坑：ST_ReducePrecision 为什么会制造接边缝隙

发表于 2026-08-05 更新于 2026-08-20 分类于 PostGIS 实战 本文字数： 3.1k 阅读时长 ≈ 11 分钟
从一个最小三角形案例解释 ST_ReducePrecision 的 snap-rounding 机制，并给出兼顾六位精度与面要素接边的处理、验证流程。

空间数据做完拓扑修复后，往往还要统一坐标精度。看起来，这只是把经纬度四舍五入到六位小数；实际用 ST_ReducePrecision 处理面数据时，却可能发现某个共享顶点消失了，两块原本严丝合缝的面之间也多出了一条细缝。

问题不在“四舍五入”，而在 ST_ReducePrecision 不只做四舍五入。它还会在新的精度模型下重建几何，并清理无法稳定表达的细小结构。

本文从一个真实案例出发，解释这种现象的成因，并整理一套适用于面覆盖数据（polygon coverage）的精度处理流程。

一、先说结论

面对“坐标落在 1e-6 网格，同时不新增接边缝隙与压盖”这个需求，先记住四点：

  1. ST_ReducePrecision 是精度归约加几何重建，不是单纯的坐标取整；它可以删除顶点，也可能让相邻面采用不同的折叠结果。
  2. ST_SnapToGrid 更接近逐坐标网格化。对共享坐标一致的相邻面使用同一原点和网格参数，双方会得到相同的共享边结果；但窄条、短边和小环仍可能退化。
  3. 浮点几何“落在六位小数网格上”与“任意方式打印都只有六位小数”不是一回事。文本输出应单独控制精度。
  4. 无论选择哪种算子，都不要原地更新后直接交付。应写入新表，并在处理前后分别检查有效性、退化、面积变化和 coverage。

三、ST_ReducePrecision 不只是“四舍五入”

ST_ReducePrecision(geom, gridsize) 的目标可以概括为：输出坐标落在指定网格上，并让结果在该精度模型下保持有效。它大致经历三个阶段：

  1. 将坐标归约到网格；
  2. 执行 snap-rounding，对相交或触碰 hot pixel 的线段重新节点化；
  3. 清理重建后产生的零面积尖刺、重复点和其他退化结构。

输入坐标已经是六位小数，只能说明第一步可能不改变它，不能保证后两步不改变几何。

这里有两个关键特征：

  • A 与 B 的距离恰好是一个网格单位；
  • 三角形 ABC 的面积恰好是一个网格单位的平方。

A 对应的 hot pixel 覆盖半个网格到半个网格的邻域。线段 B → C 恰好擦过它的角点，snap-rounding 会让这条线经过 A。环随之变成 A → B → A → C，其中 A → B → A 是零面积尖刺，清理阶段便会删掉 B。

不同 GEOS 版本在 hot pixel 边界命中细节上可能存在差异，但工程结论不变：尺寸接近网格大小的结构，在精度归约时不能视为稳定结构。

因此，让一个几何原封不动地通过 ST_ReducePrecision(g, 1e-6)，仅有“坐标能用六位小数表示”还不够。相邻点距离、点到非相邻线段的距离、窄条宽度等特征尺寸，都应明显大于一个网格单位。

四、三个容易混淆的目标

处理精度前，最好先确认真正要满足的是哪一个目标：

目标 更合适的工具 需要接受的代价
坐标落在 1e-6 网格 ST_SnapToGrid 结果可能自交、折叠或丢失小部件
单个几何在新精度模型下有效 ST_ReducePrecision 会重建几何，可能删除顶点并破坏面间接边
整层共享边同步简化 ST_CoverageSimplify 这是简化算子，不等于六位小数归约
文本只输出六位小数 ST_AsText / ST_AsGeoJSON 只控制序列化，不改变底层几何

不存在一个逐要素算子，能在所有数据上同时保证“网格化、单体有效、细节不丢、整层拓扑不变”。特征尺寸小于或接近网格时，必须做取舍并检查异常要素。

1e-6 本身就不能被二进制浮点数精确表示，除法和乘法还会继续引入舍入误差。为了让文本再次解析后得到同一个 double，17 位输出必须暴露这些尾数。

因此应该把两个需求分开：

  • 计算与存储层：检查坐标是否落在目标网格；
  • 交换与展示层：明确指定文本的小数位数。

如果下游严格要求 WKB 中每个 double 的最短十进制表示都不超过六位，这已经不是普通的“显示精度”需求。此时要么接受几何重建并做完整 coverage 验证，要么改用定点整数坐标存储，例如以 1e-6 度为单位保存为 bigint。

六、为什么不能只对部分面使用 ReducePrecision

一种常见优化思路是：只处理包含高精度节点的面，其余面不动。对 ST_ReducePrecision 而言，这并不安全。

假设面 X 与面 Y 共享边 E，只有 X 被选中。即使 E 上的坐标原本都已经落在网格上，X 仍会经历重新节点化和几何清理，Y 却保持原样。只要 X 的某个共享顶点被删除，两侧就会裂开。

即使 X、Y 同时处理，也不能据此认定安全。顶点是否折叠取决于它在各自环内的局部构型；共享边两侧的环结构不同，重建决策也可能不同。

七、一套可回滚、可验证的处理流程

以下流程以 ST_SnapToGrid 为主，目标是让共享坐标以相同规则落到网格上，同时把退化风险显式暴露出来。

1. 统计真正需要处理的要素

如果结果为 0，就不必为了“看起来更整齐”再重建几何，文本输出时限制精度即可。

2. 检查处理前的 coverage

PostGIS 3.4 及以上可以使用 coverage 窗口函数：

处理前已有的缝隙或压盖应单独记录，避免把历史问题误判为精度归约造成的问题。

3. 写入新表，不要原地 UPDATE

保留原始 geom，便于逐要素对比，也能在发现异常时快速回滚。

4. 找出无效、折叠和面积异常

这里顶点数变化不一定是错误，但它是很有价值的审查信号。lost_parts > 0、空几何或面积突变通常意味着窄条、小环已经塌掉，应回到原数据逐一处理，而不是直接发布整表。

5. 重新检查 coverage

只有将处理前后的异常边进行对比，才能回答“本次操作是否新增了缝隙或压盖”。

九、pprepair 输出还要额外防两类风险

本案例的数据已经经过 pprepair。精确拓扑修复会引入新的交点，因此还要特别关注：

  1. 距离远小于网格的节点：新交点可能只与既有节点相差微米级，snap 后会落到同一格点，形成零长边或退化环。
  2. 用于填补缝隙的窄条：宽度小于网格尺度的 sliver 可能整体消失。如果它是独立面，会留下真正的空洞；如果只是共享边上的薄凸起，则可能在两侧同步折叠。

这也是为什么“共享边会同步网格化”并不等于“整层一定仍然有效”。网格化之后，单体有效性和 coverage 都必须重新验证。

十、CoverageSimplify 能解决什么

如果真正的目标不是限制小数位，而是“按容差简化整层，并让共享边同步变化”，应使用 coverage-aware 算子：

ST_CoverageSimplify 把整组面作为一个覆盖处理，共享边只简化一次，再同步给两侧。它适合整层拓扑一致的简化，但不会替代 ST_SnapToGrid 的十进制网格归约目标。

十一、别忘了 EPSG:4326 的单位是度

本文中的 1e-6 是角度，不是米。在纬度约 41° 的位置：

  • 纬向 1e-6 度约为 0.111 m；
  • 经向 1e-6 度约为 0.084 m。

如果业务规则要求固定的米级容差，应先转换到合适的投影坐标系，例如对应区域的 CGCS2000 / Gauss-Krüger 投影带，在平面坐标中处理后再转换回 EPSG:4326。

十二、最终决策清单

需求 推荐做法
坐标统一落在 1e-6 网格 全量 ST_SnapToGrid，写入新表
只要求 WKT / GeoJSON 显示六位 ST_AsText(geom, 6) 或 ST_AsGeoJSON(geom, 6)
单个几何必须符合新精度模型 ST_ReducePrecision，并接受几何重建的代价
整层按容差简化且共享边同步 ST_CoverageSimplify 窗口函数
数据来自 pprepair 等拓扑修复工具 额外检查近邻节点、窄条、空几何和部件丢失
结果准备交付 对比处理前后 validity、coverage、顶点数、部件数与面积

真正可靠的精度处理，不是找到一个“万能函数”，而是先区分网格化、几何有效、拓扑一致和文本显示这四个目标，再用可回滚的数据流和可量化的检查把风险收住。
