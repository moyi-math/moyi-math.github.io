Learn Claude Code 01：Agent Loop——一个循环如何让 LLM 真正行动起来

发表于 2026-08-20 分类于 Learn Claude Code 本文字数： 1.6k 阅读时长 ≈ 6 分钟
从最小 Agent Loop 出发，拆解模型、工具与消息历史如何构成闭环，并解释教学实现与生产级 Claude Code 的差距。

系列定位： “Learn Claude Code” 将从一个最小可运行的 Agent 开始，逐层加入工具、权限、Hooks、任务管理、上下文压缩和多 Agent 协作。本文先回答最基础的问题：LLM 为什么套上一层循环之后，才真正成为 Agent？

五、一次任务是怎样跑起来的

以“查看当前分支，并告诉我工作区是否干净”为例：

  1. 用户问题作为第一条消息进入 messages。
  2. 模型发现需要真实的 Git 状态，生成一个 bash 工具调用。
  3. 运行框架执行命令，将 stdout、stderr 包装成 tool_result。
  4. 新的消息历史再次交给模型。
  5. 如果输出足够，模型生成自然语言结论；如果信息不足，它会继续调用工具。
  6. 响应中不再出现 tool_use，循环结束。

因此，Agent 的“自主性”并不是一次生成特别长的计划，而是能够在每次获得新证据后重新决策。

六、为什么 30 行教学代码不能直接上生产

最小循环揭示了原理，也故意忽略了很多工程问题：

教学版缺口 生产系统需要回答的问题
任意命令都能执行 哪些操作允许自动执行，哪些必须询问用户？
循环没有上限 如何限制轮数、Token、费用与总运行时间？
工具输出原样返回 超大输出如何截断、落盘或摘要？
调用失败就抛异常 超时、限流、上下文过长时怎样恢复？
只考虑单个前台任务 多工具和后台任务怎样并发而不互相踩踏？
状态只有 messages 如何追踪中止信号、压缩状态、Hooks 和恢复次数？

尤其需要注意：上面的 bash 允许模型执行任意 Shell 命令。它只适合放在隔离的临时目录中理解机制，不能直接对真实项目、生产服务器或个人主目录开放。成熟的 Agent 必须在工具执行之前增加路径约束、权限判断、用户确认和审计记录。

Claude Code 的真实查询循环虽然远比示例复杂，但复杂度主要来自这些保护与恢复机制；最核心的交互模式没有改变：调用模型 → 执行工具 → 回传结果 → 再次判断。

七、这一篇真正需要记住什么

  1. LLM 与 Agent 的差别在运行框架。 模型负责决定，框架负责让决定产生现实效果。
  2. 循环的状态是消息历史。 工具请求和工具结果必须完整配对并持续累积。
  3. 退出条件是没有新的工具调用。 有调用就继续执行，没有调用就返回最终回答。
  4. 生产复杂度来自边界保护。 权限、预算、恢复、并发和上下文管理都建立在同一个循环之上。
