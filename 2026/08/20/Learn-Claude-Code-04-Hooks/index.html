Learn Claude Code 04：Hooks——把扩展逻辑挂在循环上

发表于 2026-08-20 分类于 Learn Claude Code 本文字数： 2.1k 阅读时长 ≈ 7 分钟
用生命周期 Hook 解耦权限、日志、上下文注入和收尾检查，并分析 Hook 返回值、执行顺序与安全不变式。

系列定位： 上一篇把权限检查插入了工具执行之前，但它仍然由 Agent Loop 直接调用。本文进一步抽象生命周期 Hooks，让权限、日志、上下文注入、输出检查和收尾逻辑独立注册，而不是不断改写循环核心。

一、循环为什么会越写越胖

最初的 Agent Loop 非常清晰：调用模型、执行工具、回传结果。随着功能增加，工具执行部分很容易变成这样：

这些功能本身都合理，问题在于它们属于不同关注点：权限、可观测性、通知、结果治理和指标统计。全部硬编码进循环，会导致三个后果：

  • 修改任一扩展都要触碰核心控制流；
  • 功能顺序隐藏在散落的代码中，难以组合与测试；
  • 不同运行环境无法按需启用扩展。

Agent Loop 应当像事件循环一样“无聊而稳定”。扩展逻辑更适合挂在明确的生命周期节点上，这就是 Hooks。

二、四个事件覆盖一次完整 Agent 周期

教学版只需要四个事件，就能覆盖从输入到退出的主路径：

UserPromptSubmit 用户输入后、调用 LLM 前 校验输入、补充项目上下文
PreToolUse 参数验证后、Handler 前 权限、审计、修改工具输入
PostToolUse Handler 后、结果回传前 输出检查、指标、触发后续动作
Stop Agent 准备结束前 验收、清理、必要时要求继续

五、简单返回值很快会不够用

教学版用 None 表示继续、非 None 表示阻止，容易理解，但多个事件对返回值的需求并不相同：

  • UserPromptSubmit 可能需要追加上下文或改写输入；
  • PreToolUse 可能需要修改参数、请求权限或阻止执行；
  • PostToolUse 可能需要改写输出、记录非阻塞错误或停止后续循环；
  • Stop 可能允许结束，也可能注入反馈让模型继续修正。

因此，生产系统更适合使用结构化结果：

结构化结果把“展示消息”“阻止执行”“修改参数”“追加上下文”区分开，避免调用方从某个字符串或真假值猜测 Hook 的意图。

六、Hook 顺序本身就是业务逻辑

一个事件可以注册多个 Hook，那么注册顺序会直接影响结果。例如 PreToolUse 同时有：

  1. 参数标准化；
  2. 权限判断；
  3. 审计记录。

如果权限判断先执行，后面的 Hook 又改写了命令，实际执行内容就没有经过审批；如果短路后才记录日志，被拒绝的调用又可能完全没有审计痕迹。

更稳妥的阶段顺序是：

当 Hook 数量增加时，最好显式声明优先级或拆分更细的事件，而不是依赖“恰好按注册顺序执行”的隐式约定。

七、最重要的安全不变式：Hook 不能提升权限

Hooks 是扩展机制，不应成为绕过安全策略的后门。尤其要坚持：

Hook 返回 allow，也不能覆盖更高优先级规则给出的 deny 或不可绕过的 ask。

原因很直接：Hook 往往由项目脚本或第三方配置提供，而组织策略和用户设置代表更高层的信任边界。如果一个项目 Hook 可以把被全局禁止的发布命令改成允许，权限系统就形同虚设。

正确做法是把 Hook 的权限意见作为权限管线的一项输入，而不是最终裁决：

同理，Hook 改写工具输入后，必须对新输入重新执行验证和权限判断。

八、Stop Hook 为什么需要防无限循环

Stop Hook 很适合做任务验收。例如测试仍然失败时，它可以把“请先修复失败测试”作为新消息注入，让 Agent 继续工作：

但这里藏着一个循环：模型修正后再次准备结束，Stop Hook 又返回同样的反馈，于是永远无法退出。

九、从 4 个事件扩展到完整生命周期

四个事件足以理解模式，但真实 Coding Agent 还会关心更多阶段：

类别 可扩展事件示例
会话 启动、结束、设置变更
工具 执行前、成功后、失败后
上下文 压缩前、压缩后、指令加载
子 Agent 启动、停止、空闲
工作区 文件变化、目录变化、Worktree 创建与移除
任务 创建、完成、团队成员状态变化

事件数量可以增长，但设计原则不变：稳定内核只发布生命周期事件，扩展模块订阅事件并返回结构化结果。

十、这一篇真正需要记住什么

  1. 横切逻辑属于 Hook，不属于 Agent Loop。 权限、审计、上下文和收尾应独立注册。
  2. 生命周期事件比具体功能更稳定。 循环只知道何时触发，不需要知道谁在监听。
  3. 结构化 HookResult 优于真假值。 修改输入、阻止执行、追加上下文和停止循环应明确表达。
  4. 执行顺序必须显式设计。 修改后的输入要重新验证，被拒绝的调用也应留下审计记录。
  5. Hook 不能提升权限。 更高优先级的 deny / ask 始终拥有最终约束力。
  6. Stop Hook 必须防重入。 续跑要有状态标记、轮次上限和预算保护。

至此，Agent 已具备循环、工具、权限与扩展点，工具执行层的骨架基本完成。下一篇将进入规划与协调：用 TodoWrite 把复杂任务变成可追踪的步骤，而不是让模型边想边做、走到哪里算哪里。
