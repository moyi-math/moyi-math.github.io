Learn Claude Code 07：Skills——让专业知识按需进入上下文

发表于 2026-08-20 分类于 Learn Claude Code 本文字数： 2.4k 阅读时长 ≈ 9 分钟
从 System Prompt 膨胀出发，拆解 Skill 的两级加载、注册表、触发描述与资源引用，并厘清 Skill、Tool 和 Subagent 的职责边界。

系列定位： Subagent 解决了不同子任务之间的上下文隔离，但每个 Agent 仍然需要专业知识：前端规范、数据库约束、发布流程、代码审查清单……如果把这些文档全部塞进 System Prompt，隔离出来的新上下文依然会从一开始就很拥挤。本文引入 Skills，让知识在真正需要时才进入消息历史。

一、System Prompt 不是知识仓库

假设一个项目同时维护以下说明：

  • React 组件规范，2000 行；
  • SQL 风格与表结构说明，1500 行；
  • API 设计指南，3000 行；
  • 发布与回滚手册，1000 行。

最直接的做法是启动时全部拼进 System Prompt。但 Agent 只是修改按钮颜色时，SQL 和发布手册依然会随每次 API 请求重复发送。

这会产生四类成本：

  1. Token 成本： 无关知识在每一轮重复占用窗口；
  2. 注意力成本： 规则越多，当前任务真正需要的指令越不突出；
  3. 维护成本： 任一文档更新都会改变庞大的基础 Prompt；
  4. 冲突风险： 不同领域的规范可能给出不兼容的建议。

System Prompt 更适合承载身份、全局约束和稳定行为原则，而不是装下所有“也许有一天会用到”的知识。

二、Skills 的核心是渐进式披露

按需加载需要同时解决两个看似矛盾的问题：

  • 如果 Agent 完全不知道某项知识存在，它就不会主动加载；
  • 如果把完整知识都提前告诉 Agent，又回到了 Prompt 膨胀。

Skill 使用两级结构化解这个矛盾：

层级 常驻内容 作用 成本
目录层 名称、简短描述、触发条件 让模型知道有哪些能力可选 小，每轮携带
内容层 完整步骤、约束、示例和资源引用 真正指导当前任务 大，仅按需加载

七、Skill、Tool 和 Subagent 分别解决什么

这三个概念经常同时出现，但职责不同：

机制 核心问题 提供的东西
Tool Agent 怎样作用于外部世界 可执行动作
Skill Agent 应该怎样完成某类工作 知识与流程
Subagent 一项独立工作在哪里推理 隔离的执行上下文

以代码审查为例：

  • read_file、git diff 是 Tool；
  • 缺陷分类和审查清单是 Skill；
  • 把安全审查交给独立上下文执行的是 Subagent。

一个 Skill 还可以声明在独立上下文中运行，相当于组合“专业流程 + Subagent”。但这种组合仍应明确工具集合、模型、预算和权限模式，不能因为加载了 Skill 就默认获得额外能力。

八、多来源 Skill 如何处理冲突

真实系统中的 Skill 可能来自多个位置：

  • 产品内置；
  • 企业管理策略；
  • 用户级目录；
  • 项目级目录；
  • 插件或远程服务；
  • 命令行临时添加的目录。

这会带来同名冲突和信任问题。运行框架至少需要：

  1. 明确来源优先级，不能依赖文件系统遍历顺序；
  2. 在注册表中记录来源、真实路径和版本；
  3. 同名覆盖时给出可观察提示，而不是静默替换；
  4. 企业策略或安全禁用不能被项目 Skill 绕过；
  5. 远程内容需要固定版本、校验完整性并限制权限。

Skill 是会影响模型行为的可执行知识，风险类似代码依赖。第三方 SKILL.md 可能诱导 Agent 读取凭证、运行危险命令或忽略用户要求，因此不能把“只是 Markdown”当作安全保证。

九、按路径或任务条件缩小目录

当 Skill 数量继续增长，可以根据上下文做条件激活。例如某个 Skill 的元数据声明：

只有当前任务涉及匹配文件时，目录才展示该 Skill。这样既减少 Token，又降低错误路由概率。

但条件激活应该是“提高相关度”，不是隐藏用户明确要求的能力。用户点名某个 Skill 时，系统仍应能解析并加载，或清楚说明它为何不可用。

十、加载后的知识也会过期

Skill 一旦进入消息历史，会和其他消息一样持续占用上下文，直到会话结束、被裁剪或被摘要。此后磁盘上的 SKILL.md 即使更新，历史中的旧版本也不会自动变化。

十一、这一篇真正需要记住什么

  1. System Prompt 不是知识仓库。 全局稳定约束常驻，专业知识按需加载。
  2. Skill 采用两级甚至三级披露。 目录帮助选择，正文指导流程，资源按需读取。
  3. 描述决定路由质量。 它要清楚说明用途和触发条件，而不是宽泛宣传。
  4. 运行时按注册名称加载。 不把模型输入直接当成文件路径。
  5. Skill 提供知识，不提供授权。 引用的脚本和工具调用仍要经过权限管线。
  6. 多来源需要优先级与信任治理。 记录来源、版本和覆盖关系，防止静默劫持。
  7. 加载后的知识仍占上下文。 需要版本感知，并与后续压缩机制协作。
