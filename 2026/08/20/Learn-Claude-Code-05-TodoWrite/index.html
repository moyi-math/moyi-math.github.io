Learn Claude Code 05：TodoWrite——让 Agent 的计划看得见

发表于 2026-08-20 分类于 Learn Claude Code 本文字数： 2k 阅读时长 ≈ 7 分钟
从长任务中的目标漂移出发，拆解 TodoWrite 如何把计划变成外部状态，并分析任务粒度、状态约束、提醒机制和持久化任务系统的边界。

系列定位： 前四篇完成了 Agent 的执行骨架：循环负责持续决策，工具连接外部世界，权限守住执行边界，Hooks 承载横切逻辑。本文开始进入规划与协调，给 Agent 增加一个不执行任何实际工作的工具——TodoWrite。

一、长任务为什么容易越做越偏

给 Agent 一个简单任务，例如“读取 README 并总结”，它通常不需要计划。但如果任务变成：

统一项目中的 Python 命名风格，修复所有引用，运行测试，并更新文档。

执行几轮后，消息历史里会塞满文件内容、搜索结果、测试日志和错误堆栈。模型的注意力被眼前失败吸引，可能修完两个测试就直接宣布完成，忘记还有文档和其他引用要更新。

这不是模型“突然变笨”，而是长任务天然存在三个问题：

  • 目标被中间信息淹没： 原始要求离当前上下文越来越远；
  • 完成标准不清晰： 做过某件事，不等于验证过结果；
  • 进度只存在于自然语言中： 很难可靠判断哪些步骤未开始、正在做或已经完成。

解决办法不是让模型在开头生成一段更长的分析，而是把计划变成一种可以重复读取和更新的外部状态。

二、TodoWrite 是 Agent 的外部工作记忆

TodoWrite 不读文件、不运行命令，也不修改项目。它只维护一个带状态的任务列表：

这张列表同时服务三个角色：

角色 获得的价值
模型 每轮都能重新定位当前步骤和剩余工作
用户 可以观察进度，发现方向错误时及时纠正
运行框架 可以检查状态不变式、提醒更新或阻止草率结束

因此，TodoWrite 的价值不是“让模型会列清单”，而是把隐藏在推理过程中的计划转换为显式、结构化、可观察的状态。

四、状态流转比清单内容更重要

一张永远停留在 pending 的清单只是装饰。真正有用的是持续更新状态：

可以为计划定义几条简单不变式：

  1. 同一时刻最多一个任务处于 in_progress；
  2. 开始执行前，当前任务应从 pending 变为 in_progress；
  3. 只有得到验证证据后，任务才能标记为 completed；
  4. 任务范围变化时更新列表，而不是在列表之外偷偷增加工作；
  5. Agent 准备结束时，不应还有未解释的 pending 或 in_progress 项。

这些约束把“我觉得做完了”变成“状态与证据表明做完了”。尤其是测试、构建、格式检查等验证步骤，最好单独列项，避免把“修改代码”和“确认修改正确”混为一件事。

六、提醒机制：解决计划被遗忘，而不是强迫所有任务规划

即使提供了 todo_write，模型也可能连续多轮不更新它。教学实现可以维护一个计数器：若多轮工具调用都没有更新计划，就在下一次模型调用前追加提醒。

提醒应该满足两个条件：

  • 只在已经存在计划且计划可能过期时出现；
  • 它是上下文提示，不是假装成用户的新需求。

固定“每三轮提醒一次”适合展示机制，却不是普适策略。短任务根本不需要计划，频繁提醒还会浪费 Token、打断模型。生产系统更适合根据任务复杂度、未完成项、连续执行时间或结束前验收来动态触发。

七、TodoWrite 与持久化 Task System 有什么区别

轻量 TODO 列表适合单 Agent、单会话中的线性计划，但它不是完整的项目管理系统：

能力 TodoWrite 持久化 Task System
存储 当前进程内存 文件或数据库
结构 平铺列表 可包含依赖图
生命周期 会话结束即消失 可跨会话恢复
并发 通常无锁 需要锁与所有权
接口 整体替换列表 创建、获取、更新、查询
协作 单 Agent 自用 多 Agent 分配和协调

当需求变成“任务 B 必须等 A 完成”“多个 Agent 同时领取任务”“应用重启后继续执行”，就应升级到持久化任务系统，而不是继续往 TodoWrite 的单个数组里塞字段。

这也是一个重要的工程判断：不要因为简单列表好用，就把它无限扩张成半成品工作流引擎。

八、这一篇真正需要记住什么

  1. TodoWrite 是外部工作记忆。 它把模型内部计划变成可观察、可更新的结构化状态。
  2. 规划工具不增加执行能力。 它提升的是长任务的方向感、完整性和可纠正性。
  3. 状态流转必须有约束。 一次聚焦一个进行中任务，完成状态需要验证证据。
  4. 任务粒度要可验证。 既不能粗到失去导航，也不应细成工具调用日志。
  5. 提醒应按需触发。 固定轮数只是教学手段，生产逻辑要考虑任务复杂度与计划状态。
  6. TodoWrite 不等于 Task System。 跨会话、依赖和多 Agent 协作需要持久化任务模型。

计划解决了“接下来做什么”，却没有解决大任务产生的大量中间上下文。下一篇将引入 Subagent：把独立子任务放进新的消息历史，只把结论带回主线程。
