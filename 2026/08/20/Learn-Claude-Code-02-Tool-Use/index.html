Learn Claude Code 02：Tool Use——用分发表扩展 Agent 的能力

发表于 2026-08-20 分类于 Learn Claude Code 本文字数： 1.9k 阅读时长 ≈ 7 分钟
从单一 Bash 工具扩展到文件读写与搜索，理解工具 Schema、Handler、分发表、调用顺序和并发安全之间的关系。

系列定位： 上一篇用 Agent Loop 打通了“模型决策—工具执行—结果回传”的闭环。本文保持循环不变，专门解决另一个问题：Agent 增加新能力时，怎样避免把核心循环改成一堆 if/elif？

一、只有 Bash，能用但不好用

理论上，一个 Bash 工具几乎可以完成所有本地开发任务：

但“能做”不等于“适合作为 Agent 工具”。当模型想表达“读取文件”时，它还得把意图翻译成某个操作系统上的命令，处理引号、编码、路径和 Shell 差异。这会带来三个问题：

  • 额外推理成本： 模型需要先选择并拼接命令；
  • 不稳定： 同一个意图可能生成多种命令，边界行为难以预测；
  • 权限过大： 读一个文件与删除整个目录都经过同一个执行入口。

更合理的做法，是为高频动作提供语义明确的专用工具，例如 read_file、write_file、edit_file 和 glob。模型直接表达意图，运行框架再负责平台细节和安全边界。

这条管线把模型生成的“请求”转换成系统愿意执行的“动作”。模型输出永远只能被视为不可信输入，Schema 合法也不代表操作安全：{"path": "../../private.key"} 完全可能通过类型检查，却不应该通过路径校验。

工具输出也需要边界。搜索日志可能返回几十 MB 内容，如果原样塞回消息历史，会迅速耗尽上下文窗口。常见做法是设置结果大小上限：小结果直接返回，大结果落盘，只把摘要、预览和文件位置交给模型。

七、这一篇真正需要记住什么

  1. 一个工具包含 Schema 和 Handler。 前者服务模型决策，后者负责真实执行。
  2. 分发表隔离能力与编排。 新增工具时注册定义和实现，Agent Loop 无需跟着修改。
  3. 专用工具提供更强的语义。 语义越明确，参数验证、权限控制和审计越可靠。
  4. 并发安全取决于具体输入。 连续的安全调用可成批并发，写操作与有依赖的调用必须保序。
  5. 模型调用只是请求，不是授权。 Schema、语义校验、Hooks 和权限检查都应位于 Handler 之前。

至此，我们已经有了一个能循环、能扩展的 Agent，但它仍然可能执行危险命令。下一篇将进入 Permission：在模型决定“我要做什么”和系统真正执行之间，加上一道明确的安全门。
