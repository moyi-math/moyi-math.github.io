Learn Claude Code 03：Permission——在工具执行前加一道安全门

发表于 2026-08-20 分类于 Learn Claude Code 本文字数： 2k 阅读时长 ≈ 7 分钟
从 allow、ask、deny 三类决策出发，拆解 Agent 权限管线、规则优先级、拒绝反馈以及生产级权限系统的安全边界。

系列定位： 前两篇已经构建出可循环、可注册工具的 Agent。但模型只要生成一个合法工具调用，Handler 就会立即执行。本文在“模型提出动作”和“系统执行动作”之间加入 Permission Gate，让每个请求先经过明确的权限决策。

一、模型决定要做，不等于系统允许做

在上一篇中，我们为文件工具增加了工作区路径检查，但 bash 仍然几乎可以执行任意命令。如果用户只说“清理一下项目”，模型可能正确删除构建缓存，也可能误删重要文件。

这种风险不能靠 Prompt 里的“请小心”解决。Prompt 影响模型的决策倾向，却不是不可绕过的安全边界。真正的边界必须由模型之外的确定性代码执行：

最重要的原则是：模型只有提议权，运行框架才有执行权。

二、权限系统不是一个布尔值

把权限结果只设计成“允许 / 拒绝”，往往会在安全性和可用性之间二选一。更实用的模型至少需要三种决策：

决策 含义 典型场景
allow 风险足够低，直接执行 读取工作区文件、列目录
ask 操作可能合理，但需要本次人工确认 删除项目文件、写工作区外路径
deny 无论用户是否确认都不执行 被组织策略禁止的命令或工具

生产系统还常见第四种状态 passthrough：当前工具或规则不作决定，把请求交给后续通用权限管线。它可以避免每个工具重复实现默认策略。

三、教学版的三道闸门

为了先看清主干，可以把权限决策分成三步，并固定顺序：

  1. 检查不可放行的硬拒绝规则；
  2. 判断是否命中需要审批的风险规则；
  3. 命中风险规则时暂停，等待用户确认。

“拒绝”不是让循环崩溃，而是一条新的环境反馈。模型看到拒绝原因后，可以换一种安全方案，也可以向用户解释无法完成。若直接丢弃被拒绝的调用，消息协议会失去配对，模型也不知道动作为什么没有发生。

五、规则优先级为什么必须明确

真实项目里的规则很少只来自一个文件。个人设置、项目设置、企业策略、CLI 参数和当前会话授权都可能同时生效。此时必须定义两个问题：

  1. 多个来源冲突时，谁的优先级更高？
  2. 同一请求同时命中 allow 和 deny 时，哪个结果获胜？

一个安全的基本不变式是：高优先级的 deny 或 ask 不能被低优先级的 allow 绕过。

例如，项目规则允许执行测试命令，但企业策略禁止向外部仓库发布，那么会话里的临时“允许 Bash”不能把发布操作放行。权限合并必须保留规则来源与优先级，而不是把所有配置简单合并为最后一次匹配获胜。

六、路径限制、权限审批与沙箱不是一回事

这三个概念经常混在一起，但它们解决不同问题：

机制 解决的问题 例子
输入校验 参数是否有效 文件路径是否存在、端口是否为整数
权限决策 这次操作是否应该执行 删除文件是否需要询问用户
系统隔离 即使判断失误，最多能影响什么 进程只能访问临时工作区

权限系统会犯错，用户也可能误点允许。可靠方案必须采用纵深防御：让 Agent 运行在低权限账户或隔离容器中，只挂载必要目录，限制网络与凭证范围，并保留可审计记录。Permission Gate 是重要的一层，但不是唯一一层。

七、生产级权限管线还会增加什么

当系统从教学 Demo 演进到真实 Coding Agent，单一 evaluate_permission() 通常会拆成多个阶段：

多 Agent 场景还要处理“权限冒泡”：子 Agent 不应因为没有交互界面就静默拒绝，也不能自行放行高风险操作，而应把审批请求交给有用户交互能力的父 Agent。

自动审批同样需要谨慎。即使额外使用分类模型判断命令是否安全，它也只能优化常见请求的体验，不能替代确定性拒绝规则和系统隔离。分类器不确定或连续拒绝时，应回退到人工审批。

八、这一篇真正需要记住什么

  1. 模型提出动作，权限系统决定能否执行。 安全边界必须位于模型之外。
  2. 权限至少有 allow、ask、deny 三种结果。 ask 在可用性与安全之间提供了必要缓冲。
  3. 拒绝也是工具结果。 把原因回传给模型，循环才能自我修正并保持协议完整。
  4. 规则合并必须有优先级。 低层 allow 不能覆盖高层 deny 或不可绕过的 ask。
  5. 权限不等于沙箱。 输入校验、权限决策和系统隔离需要共同构成纵深防御。

权限已经进入工具执行路径，但如果日志、审计、输出检查等逻辑也继续硬编码进去，Agent Loop 很快会膨胀。下一篇将使用 Hooks 把这些横切能力挂在生命周期事件上，让循环继续保持稳定。
