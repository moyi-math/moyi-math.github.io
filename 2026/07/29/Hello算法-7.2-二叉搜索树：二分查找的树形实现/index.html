Hello算法 学习笔记 · 7.2 二叉搜索树：二分查找的树形实现

发表于 2026-07-30 分类于 Hello算法学习笔记 本文字数： 2k 阅读时长 ≈ 7 分钟
二叉搜索树在二叉树的基础上加了一条规则——左<根<右。这条规则让查找变成了二分查找，从 O(n) 降到 O(log n)。插入也是 O(log n)，删除要处理三种情况。理解 BST 是理解平衡树、红黑树、数据库索引的基础。

章节定位: 上节学了二叉树——一对多的层次结构。但普通二叉树的查找需要遍历整棵树（O(n)）。二叉搜索树（BST, Binary Search Tree） 在二叉树的基础上加了一条规则——左 < 根 < 右——就让查找变成了二分查找，从 O(n) 降到 O(log n)。它是平衡树（AVL、红黑树）和数据库索引的认知基础。

摘要(Abstract)

TL;DR: 二叉搜索树是节点值有序的二叉树：对于每个节点，左子树所有值 < 节点值 < 右子树所有值。这条规则让 BST 的查找、插入、删除全部变成 O(log n)——每走一步排除一半子树，和数组的二分查找是同一个思想。BST 的插入和查找逻辑相同（找位置，然后操作），删除需要分三种情况处理（无子节点、一个子节点、两个子节点）。如果插入顺序不好，BST 可能退化成链表（O(n)），这就是平衡树出现的原因。

本文覆盖:

  • BST 的规则: 左 < 根 < 右——整棵树天然有序
  • search: 二分查找的树形实现——每步排除一半
  • insert: 先查找，找到空位就挂上
  • remove 三种情况: 无子节点直接删、一个子节点子顶上、两个子节点找右子树最小替换
  • 复杂度分析: 平均 O(log n)，最坏 O(n)
  • 退化成链表: 按顺序插入导致 BST 失衡
  • 面试高频题: 3 道覆盖 BST 核心知识的面试题

适合读者: 想理解”为什么 BST 查找快”的学习者；对删除操作需要分情况感到困惑的开发者。

一、BST 的规则——左 < 根 < 右

普通二叉树对节点的值没有约束——放哪里都行。BST 加了一条规则，让整棵树天然有序：

对于每个节点：左子树中所有节点的值 < 该节点的值 < 右子树中所有节点的值

验证：

  • 节点 8：左边全是比 8 小的（4,2,6,1,3,5,7），右边全是比 8 大的（12,10,14,9,11,13,15）
  • 节点 4：左边全比 4 小（2,1,3），右边全比 4 大（6,5,7）
  • 节点 12：左边全比 12 小（10,9,11），右边全比 12 大（14,13,15）

每条规则递归地成立——左子树本身也是 BST，右子树本身也是 BST。

二、查找 search——二分查找

追踪 search(7)：

每走一步，排除掉一半的子树。 运行时间 = 树的高度（从根到目标经过的节点数）。

如上图 15 个节点的满二叉树，高度 = 4，所以查找最多 4 步。和数组二分查找完全一样。

三、插入 insert——先找位置，再挂上

追踪 insert(16)：

插入和查找的路径完全一样。 先走一遍查找路径（找空位），到了就挂上去。所以插入也是 O(log n)。

四、删除 remove——三种情况

删除是最复杂的操作，因为删完之后 BST 的规则仍然要成立。

情况 1：被删节点没有子节点（叶子节点）

情况 2：被删节点只有一个子节点

情况 3：被删节点有两个子节点

这是最复杂的情况——不能直接删，因为左右子树都需要有人管。

解法：找右子树中最小的节点，用它替换被删节点。

为什么选右子树的最小值？

右子树的最小值 = 比被删节点大的所有节点里最小的那个。

把它放到被删节点的位置：

  • 左子树所有值 < 它 ✓（它比左子树所有值都大）
  • 右子树所有值 > 它 ✓（它是右子树的最小值）

BST 规则仍然成立。

五、复杂度分析

操作 平均 最坏 说明
search O(log n) O(n) 每次排除一半子树
insert O(log n) O(n) 先查找，再挂上
remove O(log n) O(n) 先查找，再分三种情况处理
中序遍历 O(n) O(n) 遍历所有节点，输出有序序列

最坏情况 O(n) 什么时候发生？

生成的树：

BST 退化成链表了。 查找 5 要走 5 步，不是 log₂5 ≈ 2 步。

这就是为什么需要平衡二叉搜索树（AVL 树、红黑树）——它们会自动调整树的结构，保证高度始终是 O(log n)，无论插入顺序如何。

六、BST 的中序遍历 = 升序排序

BST 有一个非常重要的性质：中序遍历 BST 会得到升序序列。

这是判断一棵树是不是 BST 的经典方法：中序遍历一次，看结果是不是严格递增的。

七、面试高频题

Q1: 为什么 BST 的查找是 O(log n)？

因为 BST 的规则（左 < 根 < 右）保证每走一步就可以排除掉一半的子树。这和数组二分查找是同一个原理。BST 的高度决定了查找步数，对于满二叉树，高度 ≈ log₂n。

Q2: 删除 BST 的节点时，为什么情况 3 要选”右子树的最小值”？

左子树所有值 < 被删节点 < 右子树所有值。为了保持这个规则：

  • 新节点的值必须 > 左子树所有值
  • 新节点的值必须 < 右子树所有值

右子树的最小值正好满足这两个条件——它是比被删节点大的所有值中最小的那个。

Q3: BST 会退化吗？怎么解决？

会。如果按升序（或降序）插入，BST 会退化成链表，查找从 O(log n) 变成 O(n)。解决方法是使用自平衡二叉搜索树：AVL 树（严格平衡，每个节点左右子树高度差 ≤ 1）和红黑树（近似平衡，广泛应用于 Java TreeMap、C++ map、Linux 内核调度）。

下一节预告: 为了解决 BST 退化成链表的问题，AVL 树引入了”旋转”机制——每次插入或删除后检查平衡，如果左右子树高度差超过 1，就通过左旋/右旋调整。它是第一个真正意义上的自平衡二叉搜索树。
