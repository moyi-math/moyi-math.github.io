Hello算法 学习笔记 · 6.1 哈希表：从 O(n) 到 O(1) 的飞跃

发表于 2026-07-29 分类于 Hello算法学习笔记 本文字数： 2k 阅读时长 ≈ 7 分钟
哈希表是 Python dict 的底层原理——通过哈希函数把 key 直接映射到数组索引，把 O(n) 的查找变成 O(1)。本文从问题到解法、从简单哈希函数到完整实现逐层拆解。

章节定位: 前几章学了栈、队列这些线性结构——它们的查找都是 O(n)。哈希表通过一个精巧的”映射”机制，**把查找直接变成 O(1)**。它是 Python 里使用频率最高的数据结构之一（dict），也是理解后续很多高级结构的认知基础。

摘要(Abstract)

TL;DR: 哈希表是键值对（key-value） 的存储结构。它通过一个哈希函数（hash function） 把 key 映射成数组索引，然后直接在索引位置存取数据——这就是 O(1) 查找的来源。哈希函数有很多种设计（加法、乘法、异或、旋转），但核心目标一致：让不同的 key 均匀分布到不同索引。然而”不同的 key 算出相同索引”的情况无法完全避免，这就是哈希冲突——下一篇专门讲。

一、哈希表要解决的根本问题

前面学过的所有数据结构——数组、链表、栈、队列——查找一个元素都需要 **O(n)**：

如果数据量是 100 万，最坏情况要看 100 万次。

哈希表的思路：不要逐个比对了，直接告诉我目标在哪个位置。

二、哈希表的本质——哈希函数 + 数组

哈希表的核心思想只有两句话：

查找时：12836 % 100 = 36 → 直接去数组索引 36 取数据 → O(1)

和数组随机访问的类比：

  • 数组随机访问：已知索引 → 直接取 → O(1)
  • 哈希表查找：已知 key → 哈希函数算索引 → 直接取 → O(1)

哈希表本质上就是用哈希函数把 key 变成数组索引，从而借用数组的 O(1) 随机访问能力。

四、哈希函数设计

哈希函数的质量决定了哈希表的效率。理想哈希函数应该让不同的 key 均匀分布到不同的索引。

加法哈希

把每个字符的 ASCII 值加起来。问题："ab" 和 "ba" 会算出相同结果。

乘法哈希

每次 hash * 31 + ord(c)，字符位置会影响结果——"ab" 和 "ba" 算出来不同。

为什么用 31？ 31 是质数，31 * hash 可以被编译器优化成 (hash << 5) - hash（位运算代替乘法）。Java 的 String.hashCode() 就是用 31。这就是为什么 Java 里 "ab".hashCode() = 31×97 + 98 = 3105。

异或哈希

用异或 (^) 运算。比加法快（位运算），但同样有顺序不敏感的问题。

旋转哈希

用左移和右移混合，让每个字符的影响扩散到更多位。质量更高，但也更复杂。

Python 内置的 hash()

note

Python 的 hash() 特点：

  • 整数返回自身（hash(3) == 3）
  • 布尔值 True 的哈希是 1（False 是 0）
  • 字符串有复杂哈希算法（每个 Python 进程启动时加随机种子，防止哈希碰撞攻击）
  • 元组可哈希，列表不行（因为列表可变）
  • 自定义对象默认用 id() 做哈希

五、最简单的手写哈希表——ArrayHashMap

追踪 put(12836, "小哈")：

查询 get(12836)：12836 % 100 = 36 → 直接从 buckets[36] 取 → O(1)

但这个实现有一个致命问题：

put(10036, "小明") 会怎样？

  • hash_func(10036) = 10036 % 100 = 36
  • buckets[36] 已经有值了！
  • 新值覆盖旧值 → 12836 的数据就丢了

这就是哈希冲突——不同的 key 算出了相同的索引。下一篇专门讲怎么解决。

六、复杂度总结

操作 平均 最坏 说明
get O(1) O(n) 理想情况下无冲突，直接取
put O(1) O(n) 均摊 O(1)（扩容时 O(n)）
remove O(1) O(n) 直接置空或标记删除
最坏情况 — O(n) 所有 key 都冲突，退化成链表

最坏情况 O(n) 是什么意思？ 如果哈希函数设计极差，比如 hash(key) = 0，所有 key 都映射到索引 0——那哈希表就退化成了链表，查找变成 O(n)。
所以哈希函数的质量直接决定了哈希表的性能。

七、面试高频题

Q1: 哈希表为什么是 O(1) 查找？

哈希表通过哈希函数把 key 直接映射成数组索引。计算机访问数组是 O(1) 的（通过地址公式一步到位），所以哈希表查找也是 O(1)。本质上是用哈希函数借用了数组随机访问的能力。

Q2: Python 的 dict 和 list 在查找上有什么区别？

list 查找需要逐个比对——O(n)。dict 通过哈希函数直接定位——平均 O(1)。但 dict 有额外的哈希计算和潜在冲突处理开销，所以数据量小时 list 可能更快（哈希计算的开销 > 线性扫描的开销）。

Q3: 一个好的哈希函数应该具备什么特征？

  1. 确定性：相同的 key 必须产生相同的哈希值
  2. 高效性：计算速度要快
  3. 均匀性：不同的 key 应该均匀分布到不同索引，减少冲突
  4. 雪崩效应：输入的微小变化（改一个字符）应该导致输出的大幅变化

下一节预告: 哈希冲突是哈希表设计中必须解决的核心问题。链式地址（每个桶存一个链表）和开放寻址（冲突了就往后找空位）是两种主流解决方案。它们还涉及负载因子和动态扩容——真正工业级哈希表的关键机制。
