Hello算法 学习笔记 · 5.2 队列与双端队列：先进先出与两端的灵活

发表于 2026-07-28 分类于 Hello算法学习笔记 本文字数： 1.9k 阅读时长 ≈ 7 分钟
如果说栈是"后进先出"，队列就是"先进先出"——就像排队一样。队列的数组实现有一个精巧的"循环数组"设计，通过取模运算解决了普通数组做队列时的空间浪费问题。双端队列则是栈和队列的"合体"。

章节定位: 上节学了栈（LIFO），本节学它的镜像结构——队列（FIFO）。栈和队列是对偶的：栈在一端操作，队列在两端操作（入队在一端，出队在另一端）。栈用数组或链表实现非常简单，但队列的数组实现有一个微妙的问题需要解决——循环数组。

摘要(Abstract)

TL;DR: 队列（Queue）是 先进先出（FIFO, First In First Out） 的线性结构——就像排队一样，先到的人先被服务。入队（push）在尾部，出队（pop）在头部，全部 O(1)。队列可以用链表实现（头尾指针，天然适合），也可以用循环数组实现（通过取模运算让 rear 指针在数组末尾”折返”到开头）。双端队列（Deque） 则是在两端都可以入队和出队，是栈和队列的”合体”。

本文覆盖:

  • 队列的核心规则: FIFO——为什么它像排队
  • 链表队列: 头尾指针，入队出队全部 O(1)
  • 普通数组做队列的问题: 出队后头部空间浪费
  • 循环数组的解法: rear = (front + size) % capacity 的精细拆解
  • 取模 % 的作用: 让指针在数组末尾自动折返
  • 双端队列: 两端皆可操作的灵活结构
  • 三种数据结构对比: 栈 vs 队列 vs 双端队列
  • 面试高频题: 3 道覆盖队列核心知识的面试题

适合读者: 想知道”为什么队列的数组实现比栈复杂”的学习者；对循环数组和取模运算感到困惑的初学者。

一、队列的核心规则——先进先出

队列像排队一样简单：从尾部入队，从头部出队。

操作 作用 时间复杂度
push(x) 从尾部入队 O(1)
pop() 从头部出队 O(1)
peek() 查看队首元素（不取出） O(1)

二、链表队列——最直观的实现

链表用两个指针来追踪队列的两端：_front 指向头节点（出队端），_rear 指向尾节点（入队端）。

四、循环数组——取模的妙用

解法很简单：把数组看成一个环。 当 rear 走到数组末尾时，通过取模运算让它折返到开头。

索引 5 不存在，但 % 5 把它拉回了索引 0。 这样 push(7) 就把 7 放到了最开头的位置。

取模的本质

front + size 计算的是逻辑上的下一个空位索引，但可能超过数组末尾。% capacity 的作用就是：

front size front+size % 5 后 放到哪里
0 3 3 3 索引 3
1 2 3 3 索引 3
1 4 5 0 索引 0（折返）
2 4 6 1 索引 1（折返）
3 1 4 4 索引 4
3 3 6 1 索引 1（折返）

一句话总结取模的作用：

当 front + size 超过数组边界时，% capacity 让指针”折返”到数组头部，把数组变成一个逻辑上的环。

这样出队腾出的头部空间，可以被后续入队重新利用——一个空间都不浪费。

六、三种数据结构对比

维度 栈（Stack） 队列（Queue） 双端队列（Deque）
规则 后进先出 LIFO 先进先出 FIFO 两端皆可
入操作 push 尾部 push 尾部 append / appendleft
出操作 pop 尾部 popleft 头部 pop / popleft
查看 peek 尾部 peek 头部 两端都可
数组实现 简单（尾部操作） 循环数组（取模折返） 循环数组（两端折返）
链表实现 单指针（头部） 双指针（头尾） 双链表（前后指针）

七、面试高频题

Q1: 为什么数组栈很简单（直接在尾部操作），但数组队列需要一个”循环数组”？

栈的 push/pop 都在同一端（尾部），每次都在 len-1 处操作，空间自然复用。队列的 push 在尾部，pop 在头部——front 往前走不回头，导致腾出的空间被浪费。循环数组通过取模让 front/rear 指针在数组末尾折返，解决了这个问题。

Q2: 链表队列的头尾指针是什么原理？

_front 指向队首节点（出队时从这里取），_rear 指向队尾节点（入队时挂在这后面）。入队改 _rear.next 和 _rear，出队改 _front——各操作各的指针，互不干扰。

Q3: Python 的 collections.deque 底层是怎么实现的？

CPython 的 deque 底层是一个双向链表的块数组（array of fixed-size blocks linked in a doubly-linked list）。每个 block 存 64 个元素，block 之间用指针连接。这样既保证了 O(1) 的两端操作，又减少了链表每个节点一个指针的内存开销，同时保持了较好的缓存局部性。

下一节预告: 无论是栈、队列还是双端队列，查找都需要 O(n)——因为没有快速索引。下一章哈希表将彻底改变这一点：它用哈希函数把查找直接变成 O(1)，是 Python 里 dict 的底层原理。
