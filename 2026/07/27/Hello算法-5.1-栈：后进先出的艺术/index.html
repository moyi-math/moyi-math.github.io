Hello算法 学习笔记 · 5.1 栈：后进先出的艺术

发表于 2026-07-28 分类于 Hello算法学习笔记 本文字数： 1.9k 阅读时长 ≈ 7 分钟
栈是"后进先出"的线性结构——就像一摞盘子，后放的先拿走。理解栈的关键在于理解它的三种操作全部 O(1)：push、pop、peek。本文从数组和链表两种实现逐层拆解。

章节定位: 前两章学了数组和链表——数据的两种底层存储方式。本章的栈直接建立在它们之上，通过限制操作（只能在栈顶操作）换来了纯粹的 O(1) 效率。栈是所有后续算法（括号匹配、表达式求值、递归、DFS）的基石。

摘要(Abstract)

TL;DR: 栈（Stack）是一种 后进先出（LIFO, Last In First Out） 的线性数据结构。你只能在一端（栈顶）操作：push 入栈、pop 出栈、peek 查看栈顶。三者都是 O(1)。栈可以用数组实现（尾部当栈顶），也可以用链表实现（头部当栈顶）。理解栈的关键是理解”栈顶”只是一个标记，不是什么特殊的节点。

本文覆盖:

  • 栈的核心规则: LIFO——为什么它是”一摞盘子”
  • 三种操作: push、pop、peek——全部 O(1)
  • 数组栈实现: list.append / list.pop——尾部即栈顶
  • 链表栈实现: 头部插入/删除——每步指针变化的完整追踪
  • “栈顶”的本质: 为什么栈顶只是一个标记，不是特殊节点
  • 栈的经典应用: 函数调用栈、浏览器后退、括号匹配、表达式求值
  • 面试高频题: 3 道覆盖栈核心知识的面试题

适合读者: 想从底层理解栈的”O(1) 魔法”的初学者；对链表栈的 self._peek 含义感到困惑的学习者。

一、栈的核心规则——后进先出

栈的行为规则极其简单，只有一句话：只能在一端操作，后进来的先出去。

就像一摞盘子：

  • 新盘子叠在上面（push）
  • 要拿盘子也是从上面拿（pop）
  • 看看最上面是什么（peek）
  • 你不能从中间抽盘子（受限制的操作）

三种操作的复杂度

操作 作用 时间复杂度
push(x) 把 x 放到栈顶 O(1)
pop() 从栈顶取出元素 O(1)
peek() 查看栈顶元素（不取出） O(1)

**全部 O(1)**——这就是栈强大的地方。不管你存的 5 个元素还是 500 万个，push/pop/peek 都是常数时间。

二、数组栈——尾部即栈顶

数组栈是最直观的实现：把数组的尾部当作栈顶。

为什么是 O(1)？ list.append 和 list.pop 都在数组尾部操作——不涉及任何元素搬移。虽然容量满时的 append 会触发 O(n) 扩容，但均摊下来是 O(1)。

数组栈的”栈顶”就是数组的最后一个索引：len(self._stack) - 1。

数组栈 vs 链表栈的”栈顶标记”

实现方式 栈顶标记是什么 例子
ArrayStack 数组尾部索引 len(self._stack) - 1
LinkedListStack 指向头节点的指针 self._peek

两者本质一样——栈顶就是一个标记，告诉你”新元素该放哪，取元素该从哪取”。

  • 在数组栈里：这个标记是索引
  • 在链表栈里：这个标记是指针

五、栈的经典应用

场景 说明
函数调用栈 递归的本质——每层调用 push，返回时 pop。递归太深会”栈溢出”
浏览器后退 访问页面 push，后退 pop
括号匹配 ( { [ ] } ) — 左括号 push，遇到右括号 pop 匹配
表达式求值 3 + 5 × 2 — 操作数栈 + 运算符栈，遇到 × 优先级高就先算
撤销操作 Ctrl+Z 就是 pop 出上一步

六、面试高频题

Q1: 栈的 push/pop/peek 为什么全部是 O(1)？

因为所有操作都限制在同一端：

  • 数组栈：尾部入/出——list.append / list.pop 不涉及任何元素搬移
  • 链表栈：头部入/出——只需改 1~2 个指针

栈的本质就是通过限制操作位置，换来了极致的效率。

Q2: 链表栈的 self._peek 到底是什么？为什么它不是一个节点？

self._peek 是一个指针变量，不是节点。它存的是”指向某个 ListNode 对象的地址”。self._peek = None 表示指向空；self._peek = node 表示改指向新节点。它只是一个标记，和数组栈里的 len(self._stack) - 1（尾部索引标记）本质相同。

Q3: 用数组实现栈和用链表实现栈，各自有什么优缺点？

数组栈 链表栈
优点 实现简单、缓存友好 不会因扩容浪费空间
缺点 容量满时需要 O(n) 扩容 每个节点多存一个指针
适用 大部分场景 对扩容延迟敏感的场景

下一节预告: 和栈相对的另一种受限线性结构是队列（Queue）——先进先出（FIFO），就像排队一样。它的数组实现有一个精巧的设计——循环数组，通过取模运算解决了”出队后空间浪费”的问题。
