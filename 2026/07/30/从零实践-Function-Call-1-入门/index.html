从零实践 Function Call（一）：从 LLM 到 Agent——Function Call 入门

发表于 2026-07-30 更新于 2026-08-20 分类于 从零实践 Function Call 本文字数： 1.2k 阅读时长 ≈ 4 分钟
从一个最小工具调用示例出发，理解 LLM 如何选择工具、生成参数，并逐步进入 Agent 循环。

本文示例使用 node-llama-cpp 在本地运行 Qwen3-1.7B 模型，不需要任何 API Key 就能跑通全部代码。

一、引言

如果你和 ChatGPT 聊过天，你用的是语言模型。如果你让它”查一下明天的天气”然后它真的去查了，你用的是 Agent。

区别在哪？一句话：

LLM 只能”说”，Agent 能”做”。

LLM 再强大，它也只能基于训练数据”猜”出一个答案。它不知道现在几点，查不了数据库，算不了复杂数学，更没法操作你的文件系统。但一旦给 LLM 配上工具（Tools），这一切就变了。

这就是 Function Calling（函数调用）——让 LLM 不只是生成文本，而是能调用外部函数、获取真实数据、执行真实操作的能力。

这篇文章带你从最基础的例子开始，理解 Function Call 的全过程。

五、工具定义的三要素

三个要素缺一不可：

  • description：告诉 LLM 这个工具做什么（LLM 决策时读）
  • params：定义工具需要的参数（JSON Schema，LLM 生成参数时参考）
  • handler：真正执行的逻辑（库在执行阶段调用）

  1. 感知外部世界（读时间、查天气、查数据库）
  2. 执行精确计算（不再靠”心算”）
  3. 改变系统状态（写文件、发邮件）

这就是从 LLM 到 Agent 的第一步。
