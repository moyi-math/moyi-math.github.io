二、核心概念：Atom

AoT 把推理分解成原子步骤（Atom）。一个 atom 是最小的、不可再分的推理单元。

比如 “(15 + 7) × 3 - 10” 会被分解成：

每个 atom 包含：

  • id：唯一标识
  • kind：类型（tool / decision / final）
  • name：操作名
  • input：显式的输入参数
  • dependsOn：依赖的前序 atom

注意 <result_of_1> 这种引用——它让数据流变得显式。不是黑盒推理，而是白盒管道。

五、核心差异总结

维度 ReAct AoT
LLM 调用次数 每步 1 次 → N 次 1 次
执行者 LLM 决定下一步 系统按计划执行
验证 无 JSON Schema + 代码验证
可重现 必须重跑整套对话 可从任意 atom 重跑
错误定位 重读整个推理链 “atom 3 挂了，看输入”
测试难度 需要 mock 完整 LLM 可单独测试执行器

六、适用范围

AoT 最适合计划可预见、执行要可靠的场景：

  • 数据管道（提取 → 转换 → 加载 → 验证）
  • 金融交易（每步可审计、可回滚）
  • API 编排（调 A 拿结果 → 用结果调 B）
  • 合规敏感系统（每步都有记录）

不适合：开放性探索、头脑风暴、创意写作。
