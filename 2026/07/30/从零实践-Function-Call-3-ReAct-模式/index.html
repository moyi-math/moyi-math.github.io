二、从”单次调用”到”循环”的飞跃

之前我们看到的 Agent 都是一次交互：

但现实世界的问题往往需要多步推理。比如：

“商店周一卖 15 件、周二卖 20 件、周三卖 10 件，每件 8。平均每天卖多少件？总收入多少？"8。平均每天卖多少件？总收入多少？"8。平均每天卖多少件？总收入多少？"
这个问题无法一步解决。你需要：

  1. 算周一的收入（15 x 8）
  2. 算周二的收入（20 x 8）
  3. 算周三的收入（10 x 8）
  4. 加总得到总收入
  5. 算平均每天销量（15 + 20 + 10）/ 3
  6. 给出答案

这需要 LLM 不是只调用一次工具，而是一次又一次地调用，直到问题解决。

这个循环的关键设计

1. 第一次 vs 后续的 Prompt 策略

第一次用用户原问题，后续用”Continue your reasoning”——因为所有上下文都在对话历史里了，不需要重复问题。

2. maxTokens = 300

每次只生成 300 token，防止一次生成太多导致失控。这也是为什么需要循环——每一步只做一小件事。

3. “Answer:” 作为终止信号

System Prompt 被训练成：当模型确信已经得到最终答案时，输出 “Answer:” 然后停止。检测到这个信号就退出循环。

4. maxIterations 安全网

这是最重要的安全机制。没有这个上限，LLM 可能在循环里无限运行，消耗大量 token 和时间。生产环境中通常设置 10-30 次的上限。

五、对比：纯 LLM 推理 vs ReAct

维度 纯 LLM 推理（04_think） ReAct Agent（09_react-agent）
计算方式 模型内部”心算” 工具精确计算
步骤可见性 黑盒，只看得到结果 白盒，每步 Thought 都可见
错误定位 错了不知道在哪步 可以定位到具体 Action/Observation
回退机制 无 可以重新调用工具
可靠性 概率性的 工具保证确定性结果

六、Function Call 的两个方向：读与写

在整个系列中，我们看到了 Function Call 的两种不同类型：

读操作（Query）

工具从外部世界读取信息，返回给 LLM。LLM 再用这些信息生成回答。

写操作（Side Effect）

工具改变外部系统的状态（写入 JSON 文件），LLM 通过这副”手”来影响世界。

这两种类型覆盖了 Agent 的大部分应用场景。

七、从 ReAct 到生产级 Agent

ReAct 模式是所有现代 Agent 框架的底层模式。你可以在以下产品中看到它的身影：

  • LangChain AgentExecutor：ReAct 循环的封装版本
  • AutoGPT：自主任务的 ReAct 实现
  • ChatGPT Plugins：OpenAI 的托管版 Function Call + 循环
  • Claude Tools：Anthropic 的工具使用实现

但 ReAct 只是一个起点。生产级的 Agent 还需要：

  • 错误处理：工具调用失败时重试、降级（第 11 章）
  • 工具路由：当有几十上百个工具时，用 Embedding 预筛选（第 15 章）
  • 记忆管理：压缩、过期、重要性评分（第 8 章扩展）
  • 规划：先生成完整计划再执行（第 10 章 AoT）

工具是 LLM 的”感官”和”手”，System Prompt 是”操作手册”，循环是”工作流程”。
三者结合，就是 Agent。
