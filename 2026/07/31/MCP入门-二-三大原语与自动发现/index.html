MCP 入门（二）：三大原语与自动发现——从 FastAPI 类比理解 MCP 通信

发表于 2026-07-31 分类于 MCP 学习笔记 本文字数： 1.7k 阅读时长 ≈ 6 分钟
Resource、Tool、Prompt 是 MCP 的三大原语。本文通过和 FastAPI 逐层类比，帮你用一个下午彻底理解它们的关系、自动发现机制和传输层设计。

一、如果你会用 FastAPI，你已经会了一半

在上一篇我们看到了一个最简单的 MCP Server：

如果你是 Python 后端开发者，看到 @xxx.tool() 这种装饰器模式，应该立刻联想到 FastAPI：

FastAPI MCP
@app.get("/items/{id}") @mcp.resource("items://{id}")
@app.post("/add") @mcp.tool()
自动生成 OpenAPI /docs 自动暴露 tools/list 和 resources/list
客户端是浏览器/curl 客户端是 AI 模型

思维飞跃只有一句话：

MCP 就是”给 AI 用的 API 协议”。

二、三大原语（Server Primitives）

MCP Server 可以提供三类能力，称为 原语（Primitives）。它们分别对应 AI 与你的 Server 交互的三种方式。

1. Tool（工具）——做事情

Tool = 动作。 类似 HTTP 的 POST/PUT/DELETE。

  • AI 调用它去执行一段逻辑
  • 可以接受参数（筛选、排序、分页）
  • 可以有副作用（写入数据库、发邮件）
  • 返回结构化数据给 AI

什么时候用 Tool：需要传参数、需要逻辑处理、需要写入操作。

2. Resource（资源）——读数据

Resource = 数据。 类似 HTTP 的 GET。

  • AI “读取”一段数据，不做修改
  • 通过 URI 定位（file://、database://、api://）
  • 适合静态或动态的上下文数据

什么时候用 Resource：内容已知 URI 就能获取、只读、不需要复杂参数。

3. Prompt（提示词模板）——教 AI 怎么处理

Prompt = 模板。 预写好的提示词。

  • 让 AI 用特定的方式思考或执行任务
  • 支持参数替换（动态模板）
  • 相当于”教 AI 怎么用数据和工具”

三者关系

用一个后端的比喻来总结：

原语 比喻 类比 FastAPI
Resource 给 AI 材料（数据） GET /users/{id}
Tool 让 AI 动作（功能） POST /orders
Prompt 教 AI 方法（模板） 预填的请求体模板

三、自动发现（Auto-discovery）

这是 MCP 最巧妙的设计之一。

回到 FastAPI——当你启动 FastAPI 应用，它会自动生成 /docs 页面，列出所有接口和参数。客户端访问 /docs 就知道你的 API 长什么样。

MCP 也一样。

每个 MCP Server 启动时，会自动暴露三个”内置接口”（JSON-RPC 方法）：

MCP 方法 相当于 FastAPI 返回什么
tools/list GET /docs（工具部分） 所有工具的列表 + 参数 schema
resources/list GET /docs（资源部分） 所有资源的 URI 列表
prompts/list GET /docs（提示词部分） 所有提示词模板列表

AI 客户端连接上你的 Server 后，**第一步就是调用 tools/list**，拿到所有工具的 JSON Schema 描述，然后才知道”哦，这个 Server 能做什么”。

四、传输层：本地 vs 远程

MCP 协议本身只是一套”说好的消息格式”，它需要传输层来实际传数据。MCP 支持两种传输方式。

STDIO（本地模式）

Server 和 AI 工具在同一台机器上，通过进程的标准输入输出通信。就像你在终端跑一个 Python 脚本，输入内容看输出一样。

优点：零网络开销，简单直接。

Streamable HTTP（远程模式）

变成了你熟悉的 HTTP API 模式。Server 可以跑在云端，AI 通过网络调用。支持标准的 HTTP 认证（Bearer Token、API Key、OAuth）。

关键点：不管用什么传输方式，上面跑的 MCP 协议格式是一样的。 你可以在本地开发时用 STDIO，部署后切换到 HTTP，代码改动量很小。

七、安全模型（简述）

MCP 在设计上强调用户控制：

  • 用户授权：所有工具调用都需要用户明确同意
  • 数据隐私：数据只在用户授权范围内暴露
  • 输入校验：Server 端验证所有传入参数（自动基于类型注解）
  • 权限控制：Host 可以限制 AI 能调用哪些工具

八、总结

概念 一句话
Tool 让 AI 做事情（类似 POST）
Resource 给 AI 读数据（类似 GET）
Prompt 教 AI 怎么处理（模板）
自动发现 tools/list ≈ FastAPI 的 /docs
传输层 本地用 STDIO，远程用 HTTP
消息格式 JSON-RPC 2.0，@mcp.tool() 省掉了手写
