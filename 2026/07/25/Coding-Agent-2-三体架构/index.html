入门 Coding Agent（二）：三体架构——Agent、Model、Environment 各司其职

发表于 2026-07-25 更新于 2026-08-20 分类于 Coding Agent 原理 本文字数： 875 阅读时长 ≈ 3 分钟
以 Agent、Model、Environment 三个角色说明 Coding Agent 的职责边界、消息流和可替换性。

一、为什么需要三个角色？

上一篇我们讲了 Agent 的核心循环：推理 → 执行 → 观察 → 再推理。

这个循环涉及三种完全不同的能力：

  • 推理：调用 LLM，理解上下文，做出决策
  • 执行：在真实环境中跑命令、改文件
  • 编排：把前两者串起来，管理消息列表，处理异常

这三种能力差异太大，混在一起会导致代码臃肿、难以替换。所以 Coding Agent 的架构通常拆成三个独立的角色，各司其职。

二、三个角色的分工

1. Agent（决策循环的编排者）

Agent 是整个循环的”导演”。它不自己做推理，也不自己执行命令——它负责把其他两个角色串起来。

具体来说，Agent 做这些事：

  • 构造初始消息（system prompt + 用户任务）
  • 进入 while 循环，每一步调 Model 做推理
  • 拿到 LLM 返回的 actions 后，交给 Environment 执行
  • 把执行结果追加到消息列表
  • 处理各种异常（格式错误、超时、超限）
  • 检测退出信号，结束循环

四、这种设计的好处

可替换性是这种架构的核心优势。三个角色都有明确定义的接口（在 Python 中通常用 Protocol 或抽象类表示），你可以替换任意一个而不影响其他两个：

  • 换 Model：今天用 OpenAI，明天换 Anthropic，后天换本地模型。只要实现同一个接口就行
  • 换 Environment：本地开发用 LocalEnvironment，跑 benchmark 用 DockerEnvironment，部署用 RemoteEnvironment
  • 换 Agent：要交互式确认的用 InteractiveAgent，要全自动的用 DefaultAgent

每个角色都足够简单——Model 只管翻译，Environment 只管执行，Agent 只管循环。组合在一起就能完成复杂任务。

五、小结

角色 职责 核心方法
Agent 编排推理→执行→观察的循环 run(task), step(), query()
Model 在 Agent 和 LLM 之间做双向翻译 query(messages), format_message(), format_observation_messages()
Environment 执行 action（通常是 shell 命令）并返回结果 execute(action)
