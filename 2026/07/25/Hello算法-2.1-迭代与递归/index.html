Hello算法 学习笔记 · 2.1 迭代与递归

发表于 2026-07-26 分类于 Hello算法学习笔记 本文字数： 2.3k 阅读时长 ≈ 8 分钟
迭代是"重复"，递归是"递推"——两种最基本的程序执行方式看似不同，本质相通。本文从代码到执行过程逐层拆解，为后续时间复杂度打下基础。

章节定位: 这是《Hello算法》第二章”计算复杂度”的开篇。2.1 介绍算法效率评估的宏观概念后，2.2 节就进入最核心的基础——迭代与递归。它们是代码执行的两种基本范式，也是理解后续所有复杂度分析的前提。

摘要(Abstract)

TL;DR: 迭代(Iteration) 是”重复执行某段代码”——用 for 或 while 循环控制次数；递归(Recursion) 是”函数调用自己”——用调用栈隐式管理重复。两者本质相通：迭代可以模拟递归（显式栈），递归也可以表达迭代（尾递归）。理解它们的关键不在于语法，而在于操作次数和输入规模之间的关系——这正是下一节时间复杂度的核心。

本文覆盖:

  • for 循环: 次数已知的重复，最直观的迭代形式
  • while 循环: 条件驱动的重复，更灵活的控制
  • 嵌套循环: 外层 × 内层 = 总操作数，O(n²) 的雏形
  • 基本递归: “递”与”归”的完整执行过程拆解
  • 递归 vs 迭代: 用栈模拟递归，证明本质相通
  • 尾递归: 特殊的递归形式，及 Python 的局限性
  • 斐波那契数列: 递归的经典案例，引出重叠子问题
  • 面试高频题: 3 道覆盖迭代与递归核心知识的面试题

适合读者: 刚接触算法、想系统梳理基础概念的初学者；需要为学习时间/空间复杂度做准备的开发者。

一、迭代：重复的力量

迭代是程序最朴素的重复执行方式。你告诉计算机”做某件事 N 次”，它就老老实实做 N 次。它的核心在于循环变量和终止条件。

1.1 for 循环——次数已知的重复

这是最常见的迭代形式。range(1, n+1) 生成序列 [1, 2, ..., n]，循环体内的 res += i 执行恰好 n 次。

执行过程追踪(n=5):
res = 0
→ i=1: res = 0+1 = 1
→ i=2: res = 1+2 = 3
→ i=3: res = 3+3 = 6
→ i=4: res = 6+4 = 10
→ i=5: res = 10+5 = 15
结果: 15 = 1+2+3+4+5

关键洞察: 循环执行次数 = n。这里的 n 就是”输入规模”，操作次数和 n 成正比。

1.2 while 循环——条件驱动的重复

和 for 循环做的事完全一样，但你需要手动管理三要素: 初始化变量、检查条件、更新变量。

1.3 嵌套循环——O(n²) 的起点

外层跑 n 次，内层每次也跑 n 次，总执行次数 = n × n = n²。

  • n=10 → 100 次操作
  • n=100 → 10,000 次操作
  • n=1000 → 1,000,000 次操作

规模每扩大 10 倍，操作量扩大 100 倍。

1.4 迭代小结

形式 适用场景 复杂度直觉
for i in range(n) 次数已知 O(n)
while + 简单递增 条件复杂 O(n)
while + 翻倍更新 快速收敛 O(log n)
嵌套 for 组合遍历 O(n²)

二、递归：自己调用自己

如果说迭代是”重复”，递归就是”递推”——把一个大问题拆成更小的同类问题来解决。

2.1 基本递归——递与归

执行过程完全追踪(n=5):

递(递推): 不断调用自己，每层把 n-1 传下去，直到 n=1
归(回归): 从最深层开始返回，每层用返回的结果计算自己的结果

关键洞察: 递归依赖于系统调用栈(Call Stack)。每次函数调用都会在栈上压入一帧，返回时再弹出。递归深度 = 栈的深度。

这证明了递归和迭代在计算能力上是等价的。 任何递归都可以用迭代+显式栈重写。区别只在于：

  • 递归：栈由系统隐式管理，代码更简洁
  • 迭代：栈由程序员显式管理，控制更精细

2.3 尾递归——特殊的递归形式

和普通递归的关键区别：递归调用是函数的最后一个操作，没有任何额外的计算跟在后面。

尾递归的优化潜力: 一些编译器可以复用当前栈帧，把尾递归优化成循环，避免栈溢出。但 Python 默认不做尾递归优化，深递归仍然会报 RecursionError。

问题: 大量重复计算

  • fib(3) 被计算了 2 次
  • fib(2) 被计算了 3 次
  • n 增大时，重复计算的次数呈指数增长

这就是为什么 fib(50) 用纯递归跑不动——**时间复杂度是 O(2ⁿ)**。以每秒 1 亿次算也要 100 多天。

这引出后续章节的核心主题:

  • 记忆化递归(备忘录): 把算过的结果存下来
  • 动态规划: 自底向上的递推，避免重复计算

2.5 递归的时间复杂度速查

递归形式 递归关系 时间复杂度 示例
单分支递推 T(n) = T(n-1) + O(1) O(n) recur(n) = n + recur(n-1)
双分支指数 T(n) = 2·T(n-1) + O(1) O(2ⁿ) fib(n) = fib(n-1) + fib(n-2)
二分递归 T(n) = 2·T(n/2) + O(1) O(n) 树遍历
二分合并 T(n) = 2·T(n/2) + O(n) O(n log n) 归并排序

三、迭代 vs 递归: 对比总结

维度 迭代 递归
定义 循环执行代码块 函数调用自身
栈管理 无需额外栈 依赖系统调用栈
代码可读性 通常较直白 对树/分治问题更简洁
性能 快，无函数调用开销 有调用栈和返回开销
风险 — 深度过大导致栈溢出
本质 显式控制流程 隐式利用调用栈
典型场景 数组遍历、逐行处理 树的遍历、分治、回溯

选择原则:

  • 简单线性问题 → 迭代 (更高效、更安全)
  • 树/图/分治问题 → 递归 (代码更清晰)
  • 确定递归深度可控 → 递归
  • 深度可能很大(>1000) → 迭代或尾递归(如果语言支持优化)

四、面试高频题

Q1: 递归和迭代可以相互转换吗？

可以。 任何递归都可以用迭代+显式栈来模拟。但某些场景下递归的代码简洁度是迭代无法比拟的——比如树的遍历、汉诺塔问题。两者在计算能力上是图灵等价的。

Q2: 什么是尾递归？它和普通递归有什么区别？

尾递归是指递归调用是函数体中最后一条执行语句，且函数的返回值直接是递归调用的返回值(不做额外计算)。尾递归可以被编译器优化为循环(尾调用优化，TCO)，从而避免栈溢出。Python 不做这个优化。

Q3: fib(50) 用递归计算为什么极慢？如何改进？

因为 fib(n) = fib(n-1) + fib(n-2) 会产生指数级的分支调用，大量子问题被重复计算。改进方案:

  1. 记忆化(Memoization): 用一个字典存已经算过的值
  2. 迭代: 自底向上递推 a, b = b, a+b
  3. 动态规划: 这是 DP 的入门级案例

下一节预告: 理解了”操作次数”和”输入规模”的关系后，我们就可以系统学习时间复杂度——用大O表示法精确描述算法的效率。从 O(1) 到 O(n!)，一一拆解。
