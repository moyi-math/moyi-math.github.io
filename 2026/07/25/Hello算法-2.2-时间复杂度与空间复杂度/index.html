Hello算法 学习笔记 · 2.2 时间复杂度与空间复杂度

发表于 2026-07-26 分类于 Hello算法学习笔记 本文字数： 2.6k 阅读时长 ≈ 9 分钟
如何科学衡量算法的效率？大O表示法告诉你算法随输入规模增长的"增长趋势"，而不是精确的运行秒数。从 O(1) 到 O(n!)，七个常见复杂度一一拆解。

章节定位: 上节学了迭代与递归——理解了”操作次数”和”输入规模”的关系。本节正式引入大O表示法，系统学习如何衡量算法的时间和空间效率。这是后续所有数据结构与算法分析的共同语言。

摘要(Abstract)

TL;DR: 大O表示法描述的是算法效率随输入规模 n 增长的变化趋势，不是精确的运行时间。它的核心规则是：忽略常数，只保留最高阶。掌握从 O(1) → O(log n) → O(n) → O(n log n) → O(n²) → O(2ⁿ) → O(n!) 这七个常见复杂度阶，你就拥有了分析任何算法效率的基本工具。

本文覆盖:

  • 大O表示法: 定义、规则、为什么忽略常数和低阶项
  • 七大时间复杂度: 每个都有 Python 代码、运行数据、直觉解释
  • 空间复杂度: 七大复杂度在内存占用上的对应表现
  • 满二叉树的 O(2ⁿ): 从代码到递归树的完整追踪
  • 时空权衡: 为什么有时”用空间换时间”是值得的
  • 面试高频题: 3 道覆盖复杂度分析核心知识的面试题

适合读者: 想系统理解大O表示法、建立算法效率直觉的初学者；准备算法面试的开发者。

一、大O表示法

1.1 为什么需要大O？

运行同样的算法，你的电脑可能比别人的快 2 倍——但这不说明你的算法更好。我们需要的是一种和硬件无关、只描述算法本身效率的度量方式。

大O表示法定义: T(n) = O(f(n)) 表示当 n 足够大时，运行时间 T(n) 的增长速度不超过 f(n) 的常数倍。

1.2 核心规则

为什么可以这样简化？

1. 忽略常数系数
3n² 和 1000n² 在大 O 里都是 O(n²)。常数只反映硬件差异，不反映算法本质。

2. 只保留最高阶项
n² + n + 1 → 只看 n²。当 n=10000 时，n²=100000000，而 n=10000，1=1——低阶项的影响可以忽略。

3. 大 O 描述的是”增长趋势”，不是精确值

  • O(n) 意味着：n 翻倍，操作数也翻倍
  • O(n²) 意味着：n 翻倍，操作数翻 4 倍
  • O(2ⁿ) 意味着：n 加 1，操作数翻倍

二、七大时间复杂度

以下所有代码和运行数据都来自 hello-algo 项目，n=8。

2.1 O(1) 常数阶——与 n 无关

特征: 无论 n 多大，操作次数是固定的。数组随机访问、哈希表查找都是 O(1)。这是最理想的复杂度。

2.2 O(log n) 对数阶——效率之王

“砍半”是 O(log n) 的标志: 每次循环都把问题规模减半，循环次数就是 log₂n。二分查找就是 O(log n)——在 100 万条数据中找一个数，最多只需 20 次比较。

2.3 O(n) 线性阶——与 n 成正比

特征: 一层循环，遍历所有元素。数组遍历、链表查找都是 O(n)。

2.4 O(n log n) 线性对数阶——分治的代价

特征: 递归二分(共 log n 层)，每层做 n 次操作。归并排序、快速排序、堆排序都是 O(n log n)——这是分治思想的典型复杂度。

2.5 O(n²) 平方阶——两层嵌套

note

特征: 两层嵌套循环。冒泡排序、选择排序、插入排序都是 O(n²)。当 n > 1000 时，O(n²) 的算法就开始明显变慢。

2.6 O(2ⁿ) 指数阶——增长恐怖

递归版本(斐波那契):

指数增长有多可怕?
n=1 时操作数 1，n=10 时操作数 1023，n=20 时操作数约 100万，n=30 时约 10亿。
n 每增加 1，操作数翻倍。 这就是为什么指数级算法只能处理很小的 n。

2.7 O(n!) 阶乘阶——最慢的常见复杂度

特征: n 个分支，每个分支又产生 n-1 个子分支。旅行商问题的暴力解法就是 O(n!)。

三、空间复杂度

时间复杂度和空间复杂度是对偶的：时间看操作次数，空间看内存占用。

3.1 空间复杂度的七大阶

O(1) 常数阶

O(n) 线性阶

递归版本: 递归 n 层，调用栈占 O(n) 空间。

O(n²) 平方阶

O(2ⁿ) 指数阶——满二叉树

重点拆解: 满二叉树为什么是 O(2ⁿ)?

核心原因: 每个节点分裂出两个子节点，每层节点数翻倍。

  • 层 0: 2⁰ = 1
  • 层 1: 2¹ = 2
  • 层 2: 2² = 4
  • 层 k: 2ᵏ

总节点数 = 2ⁿ - 1

  • n=5: 2⁵-1 = 31 个节点
  • n=10: 2¹⁰-1 = 1023 个节点
  • n=20: 2²⁰-1 ≈ 100 万个节点

这就是 O(2ⁿ) 的由来——每深入一层，节点数翻倍。

四、时空权衡

很多时候，时间和空间不可兼得:

场景 做法 时间复杂度 空间复杂度
斐波那契(纯递归) 直接递归 O(2ⁿ) O(n)
斐波那契(记忆化) 加缓存 O(n) O(n)
斐波那契(迭代) 滚动变量 O(n) O(1)

用空间换时间 是最常见的优化策略:

  • 缓存/记忆化: 用 O(n) 空间把 O(2ⁿ) 降到 O(n)
  • 哈希表: 用 O(n) 空间把 O(n) 查找降到 O(1)
  • 预计算: 在数据量大、查询频繁的场景，提前算好存起来

但也要注意反过来的情形: 某些嵌入式系统内存极小，可能需要”用时间换空间”——比如解压算法，用 CPU 时间去换存储空间。

时间复杂度是数据结构与算法的”通用语言”。掌握它之后，你就可以:

  1. 分析任何算法的效率: 排序、搜索、图算法……
  2. 在不同方案间做选择: 用 O(n log n) 的排序还是 O(n²) 的？
  3. 理解后续章节: 树的高度是 O(log n)、哈希表的查找是 O(1)、动态规划的本质是避免指数爆炸

六、面试高频题

Q1: 大O、大Θ、大Ω 的区别？

  • 大O (O): 上界——最坏情况，算法不会比这个更慢
  • 大Ω (Ω): 下界——最好情况，算法至少这么快
  • 大Θ (Θ): 紧界——既是上界也是下界

日常使用中”大O”常被用来表示最坏情况，但严格来说大O只是上界。面试中一般问”时间复杂度”默认指最坏情况的大O。

Q2: O(2ⁿ) 和 O(n²) 哪个增长更快？直观感受是什么？

O(2ⁿ) 快得多。 当 n=10 时，n²=100，2ⁿ=1024；n=20 时，n²=400，2ⁿ=大约 100 万。指数增长的本质是每加 1 就翻倍，而平方增长只是乘一个固定的 n。

Q3: 什么是”用空间换时间”？举一个例子。

“用空间换时间”是指用额外的内存来减少计算时间。经典例子：斐波那契数列的记忆化递归——用一个字典存已经算过的结果，避免重复计算。纯递归 O(2ⁿ) → 记忆化后 O(n)，代价是用了 O(n) 的额外空间。
