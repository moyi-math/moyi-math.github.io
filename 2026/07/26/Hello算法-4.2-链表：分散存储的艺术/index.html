Hello算法 学习笔记 · 4.2 链表：分散存储的艺术

发表于 2026-07-27 分类于 Hello算法学习笔记 本文字数： 1.9k 阅读时长 ≈ 7 分钟
如果说数组是"连续"的王者，链表就是"分散"的艺术。插入 O(1)、删除 O(1)——链表用指针换来了数组做不到的事。本文从节点结构到代码实现，再到自己动手写一个动态数组，彻底理解两种底层结构。

章节定位: 上节学了数组——连续内存、随机访问 O(1)。本节学它的对立面——链表。链表在内存中分散存储，用指针串联节点。它和数组互为补充：数组擅长的链表弱，链表擅长的数组弱。理解这组对偶关系，是所有数据结构的起点。

摘要(Abstract)

TL;DR: 链表的每个节点包含值(val)和指向下一个节点的指针(next)，节点在内存中散落分布。插入和删除只需改指针 → **O(1)**；但访问必须从头遍历 → **O(n)**。数组和链表是数据结构世界的”阴阳”两面，几乎所有高级结构（栈、队列、哈希表、树）都可以用这两种方式实现。

四、访问节点——O(n)

这就是链表的致命弱点。

数组找 arr[3]：首地址 + 3 × 4 → 一步到位。
链表找 access(head, 3)：head → n0 → n1 → n2 → n3 → 走 3 步。

  • 链表的第 1000 个节点比第 1 个节点慢 1000 倍
  • 数组的第 1000 个和第 1 个一样快

五、查找节点——O(n)

和数组一样，查找没有捷径。但是原因不同：

  • 数组：无法直接知道值在哪个位置
  • 链表：即使知道值存在，也得从头遍历才能到达它

六、数组 vs 链表——黄金对比

维度 数组 链表
存储方式 连续内存 分散内存 + 指针
随机访问 O(1) ✅ O(n)
插入 O(n) O(1) ✅
删除 O(n) O(1) ✅
查找 O(n) O(n)
内存效率 紧凑，无额外开销 每个节点多存一个指针(8字节)
CPU 缓存 ✅ 连续读取，缓存友好 ❌ 散落分布，缓存不友好
扩容 需要 O(n) 拷贝 天然支持

怎么选？

实际工程中的偏向: 绝大多数情况下数组比链表更受欢迎。因为现代 CPU 有缓存预取机制——数组的连续内存使得相邻元素能一起被加载到缓存，而链表的散落内存会导致大量缓存未命中。这个区别在数据量大时可能是 10 倍以上的性能差距。

八、面试高频题

Q1: 数组和链表的核心区别是什么？

存储方式不同。 数组在内存中连续排列，链表分散存储并通过指针串联。这导致：

  • 数组：随机访问 O(1)，插入删除 O(n)
  • 链表：随机访问 O(n)，插入删除 O(1)

Q2: 为什么实际工程中数组比链表更常用？

虽然链表在插入删除上有理论优势，但实际中数组有两个压倒性优势：

  1. CPU 缓存友好：数组连续读取，能利用缓存行预取；链表随机访问导致大量缓存未命中
  2. 内存效率高：链表每个节点需要额外存储指针（8 字节/节点），内存开销大

大多数场景下，数组的 O(n) 插入删除可以通过在尾部操作来规避，但链表的 O(n) 随机访问是逃不掉的。

Q3: Python 的 list.append 为什么是 O(1) 而不是 O(n)？

虽然容量满时需要 O(n) 的扩容拷贝，但扩容后容量翻倍，后续 n 次 append 都不用再扩容。均摊分析：n 次 append 的总复杂度为 O(n)，平均每次为 O(1)。这就是”均摊常数时间”的含义。
