Hello算法 学习笔记 · 4.1 数组：连续内存的威力

发表于 2026-07-27 分类于 Hello算法学习笔记 本文字数： 1.7k 阅读时长 ≈ 6 分钟
数组是最基础的数据结构——元素在内存中连续排列。随机访问 O(1) 是它的王牌，但插入删除需要搬移整个后续元素。本文从代码到内存布局逐层拆解，带你彻底理解数组。

章节定位: 前两章学习了计算复杂度和数据结构分类。本章进入第一个真正的数据结构——数组。数组是所有数据结构的底层基石：栈、队列、哈希表、堆乃至图，底层都依赖数组或数组的思想。

摘要(Abstract)

TL;DR: 数组是存储在连续内存空间中的相同类型元素的集合。它的核心特性是随机访问 O(1)——只要知道索引，计算机通过 首地址 + 索引 × 元素大小 一步就能找到目标。代价是插入和删除需要搬移元素，最坏情况 O(n)。Python 的 list 本质上是动态数组，在数组之上加了自动扩容的能力。

  • 数组的初始化: 在 Python 中创建固定长度数组的方式
  • 随机访问 O(1): 为什么数组访问这么快——内存地址计算
  • 插入与删除 O(n): “从后往前”和”从前往后”搬移的完整追踪
  • 长度扩展: 为什么数组长度固定？如何手动扩容？
  • 查找 O(n): 数组的唯一弱项
  • 面试高频题: 3 道覆盖数组核心知识的面试题

适合读者: 刚接触数据结构、想从最底层理解数组的初学者。

六、长度扩展——O(n)

数组在初始化时长度就固定了。要”变长”，只能创建新数组再拷贝：

需要拷贝所有元素 → O(n)

这正是 Python 的 list 底层做的事。 当你 append 时，如果底层数组满了，Python 会分配一个更大的新数组（通常是当前容量的 1.125 倍或 2 倍），把所有元素拷贝过去，然后释放旧数组。这就是动态数组的”均摊 O(1) append”的奥秘。

七、数组复杂度总结

操作 时间复杂度 说明
随机访问 O(1) ✅ 地址公式一步到位，数组的王牌
插入 O(n) 尾部 O(1)，其他位置需要搬移
删除 O(n) 尾部 O(1)，其他位置需要搬移
查找 O(n) 没有任何捷径
长度扩展 O(n) 创建新数组 + 拷贝所有元素

一句话记：

随机访问最快(O(1))，增删最慢(O(n))，查找没捷径(O(n))。

八、面试高频题

Q1: 为什么数组的随机访问是 O(1) 而链表不是？

因为数组元素在内存中连续排列。计算机通过 首地址 + 索引 × 元素大小 一步就能算出目标地址。链表元素分散存储，必须从头节点开始沿着指针一个个走，所以是 O(n)。

Q2: 数组插入时为什么要从后往前遍历？从前往后会怎样？

从前往后遍历会把尚未移动的元素覆盖掉，导致数据丢失。从后往前遍历可以确保每个元素在覆盖之前已经先被移走了。

Q3: 动态数组（如 Python 的 list）的 append 为什么是”均摊 O(1)”？

虽然容量满时需要 O(n) 的扩容，但扩容后数组变大了（通常翻倍），后续很多次 append 都不会再触发扩容。把一次 O(n) 的开销分摊到多次 O(1) 的操作上，平均就是 O(1)。
